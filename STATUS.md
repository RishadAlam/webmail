# Postroom status — November 1, 2026

**Runnable local milestone: Phase 0 foundation plus functioning desktop/mobile mail slices. Not ready for live mail or production deployment.** The starting workspace contained the specifications, with no application or test suite. The implementation now runs on Laravel **13.39.0**, React 19 and Inertia 3, with locked dependencies and a local PostgreSQL Docker profile.

No deployment, real email delivery, provider verification, DNS/routing change, R2 activation, paid service, overage or artificial keep-alive has occurred. No live credentials were requested or used. Every fixture and screenshot is fictional.

## What works locally

**Mail UI:** Gmail-familiar full-width list → conversation, optional right pane at sufficient width, collapsible navigation, original Postroom identity, light/dark themes and density preferences. Phones have dedicated full-screen compose/search/read routes, navigation and contextual sheets, avatar selection, configurable swipes and explicit alternatives. No decorative bottom navigation or unsupported Google modules.

**Complete local mail slices:** mailbox-scoped list/search/read; star/read/archive/spam/trash/label and version-checked Undo; compose/reply/reply-all/forward drafts; permitted From identities, To/Cc/Bcc validation, serialized/versioned autosave, resume, minimize/expand/resize, guarded Close/Back/navigation, quota-held drafts and simulator acceptance. Definite failures can be copied to a new editable draft; uncertainty prevents blind resending. Settings and the Admin return route preserve compose and navigation state.

**Administration:** owner/admin requires a current MFA-verified session. Create/suspend accounts, mailbox/usage views, delivery/audit summaries. Creation needs no ordinary-user provider account and explicitly reports receiving as **pending directory synchronization**. Administrators do not automatically gain access to other mailboxes. Suspension invalidates sessions; sending rechecks current active membership transactionally after slow usage lookup.

**Durability and delivery:** Worker stores bounded original MIME in local D1 before accepting it, including encoded-storage accounting. Leases and signed claim/ack requests support replay-safe imports; main database commit precedes acknowledgment. Accepted-but-unimported items are never automatically discarded. Outbound intent, immutable payload, stored message and recipient reservation commit before provider dispatch. A concurrent repeated request claims one dispatch. Signed events are durable/deduplicated and track each recipient; early callbacks cannot be overwritten by a late acceptance response. Stalled dispatch becomes uncertain and keeps its reservation.

**Safety:** server-side mailbox/From authorization, no public signup, admin MFA, request throttling, encrypted body/MIME/payload fields, encrypted private Inertia history, private no-store responses, logout/account revalidation, scriptless sandboxed sanitized HTML and blocked remote images. Attachments remain inside original MIME only; attachment upload/download and arbitrary URL fetching are disabled. No claim of end-to-end encryption: metadata and D1 spool are not application-level encrypted, and the server holds the application key.

**Usage:** local/provider-reported/unavailable/stale are distinct. Failed refresh preserves the last value as stale and blocks sending; a short failure backoff avoids repeated provider calls. Unresolved reservations are conservatively combined with provider counters, possibly holding more mail than necessary. Current PostgreSQL physical size is measured separately from logical content; it is not whole-project Neon consumption. Other inaccessible metrics stay unavailable, without a fabricated percentage.

**Public PWA shell:** original manifest/icons, exact allowlist of public static assets, public offline explanation, no private caching/push/background send, and no forced reload over drafts. Offline in-view edits are not durable across reload/device failure.

## Unverified and unfinished — do not release yet

1. **Live provider gates (blocked, not failed):** no Cloudflare account/token/domain, D1 deployment, real incoming MIME, offline PHP-host recovery, real Resend send/webhook/usage query, actual quota reset observation or Cloudflare Free CPU benchmark. Local D1 persistence and mocked Laravel imports do not prove internet email delivery. The documented Resend daily-window discrepancy remains open.
2. **Administration integration:** setup/credential connection and rotation wizard, actual domain verification/DNS diff approval, provisioning state machine, recipient-directory synchronization, complete aliases/shared-mailbox management, incident reconciliation and safe administrator recovery are not implemented. The Cloudflare adapter is bounded paginated **read-only inspection**, with a deterministic mock. These are required before routine mailbox administration is complete.
3. **Retention/recovery:** backup/export/restore drill, emergency recovery and cleanup/purge UI are not implemented. Trash is reversible logical placement, not a space-reclaiming purge. A full store holds new work; accepted unimported data is preserved, but complete incident diagnosis/remediation is still needed. Protect the application key along with backups before live use.
4. **Deployment:** no hardened Render image, deployed HTTPS/cookie/proxy configuration, Neon project/account confirmation, free-tier billing guard review, cold-start observation or capacity certification. `Dockerfile.local` uses PHP's development server and is not a production image.
5. **Devices/accessibility:** no physical iPhone/Android keyboard, home-screen install/standalone, safe-area/gesture or VoiceOver/TalkBack/NVDA run. Emulation is explicitly labeled. Enlarged text, larger mailboxes/recipient sets, wide newsletters, worker-update-while-dirty and several full checklist combinations remain unrun; see the case-by-case report.
6. **Limited pilot features:** search covers sender names/addresses and subjects in the selected folder, not arbitrary full-text MIME. Thread correlation uses In-Reply-To; richer References/history merging is unfinished. Attachments, push and durable offline drafts are unavailable. Public password-reset email is disabled because a quota-governed verified recovery transport is not implemented; authenticated password changes work, and production administrator recovery remains a gate.
