# WebMail by Hookstack — November 1, 2026

**Reviewed local pilot with functioning mail and administration workflows; not yet approved for live production mail.** The application is renamed **WebMail by Hookstack** and remains on locked Laravel **13.39.0**, React 19 and Inertia 3. The Gmail-inspired desktop layout and distinct full-screen mobile flows share the same server drafts, permissions and navigation state.

No live credentials, real email, external deployment, DNS/routing change, R2 activation, paid service, overage or artificial keep-alive was used. Provider success in local tests is explicitly simulated or based on fictional HTTP contracts. Render states that Free instances are unsuitable for production applications; strict-free hosting therefore remains a limited pilot without a business-mail availability guarantee. [Render Free documentation](https://render.com/docs/free)

## Implemented and reviewed

**Mail and design:** Gmail-familiar broad list → conversation, optional right reading pane, collapsible navigation, original envelope/wordmark/byline, coherent light/dark colors, density and shared persisted appearance. Authentication, password confirmation, MFA, settings and administration now share the product identity and accessible tokens. Mobile has full-screen compose/search/read routes, a section drawer for administration, focus-managed sheets, explicit selection exit and usable primary touch controls. Enlarged text uses relative line heights; wide sanitized tables scroll inside the protected email view.

**Complete local mail workflows:** authorized all-mail metadata search with explicit scope; query/filter/pagination/scroll/focus restoration; 30-message conversation pages with honest visible-message action labels; star/read/archive/spam/Trash/labels and version-checked Undo. Mark unread returns to the list. Reply-To and original To/Cc are preserved; Reply all excludes the user's permitted identities. One versioned draft survives resize, minimize, account settings and password confirmation. Unfinished To/Cc/Bcc text is shared across layout remounts; queued saves remain serialized and the saved label follows actual content state. Save/network/quota errors retain drafts; ambiguous sends remain locked against blind retransmission. Permitted From addresses, recipient validation and quota reservations remain server-enforced.

**Administration:** active owner/admin plus current-session MFA; administrator-managed identities; user creation/suspension/reinstatement, member password reset and session revocation; bounded aliases, shared mailboxes, explicit member/send permissions and storage allocations. Administrators gain no implicit mail access and cannot use these controls to grant themselves access. Manual alias disabling survives suspension/reinstatement. Owner/admin passkey login is rejected because it cannot establish the required TOTP session; member passkey login retains its existing flow. Auth throttling retains its limits and now displays an actionable field error instead of a raw Inertia error page.

**Connections and receiving directory:** owner-only encrypted save/rotation/explicit clear, masked responses, recent-password confirmation and bounded read-only Cloudflare/Resend checks. Worker origins are restricted; provider redirects/partial pagination success are rejected; Cloudflare inspection has a whole-operation deadline. Directory snapshots are durable, signed, versioned, bounded, atomic and idempotent. Failed or ambiguous publication retries the same content; concurrent edits remain pending. Local synchronization says simulated, not live verified. Ordinary users need no provider account.

**Durability, delivery and retention:** bounded original MIME reaches D1 before acceptance; database import commits before acknowledgement. Imports/callbacks are replay-safe, with accepted-but-unimported mail retained. Send intent, immutable payload, stored message and quota reservation commit before dispatch; acceptance, delivery and uncertainty stay distinct. Authorized users can export original `.eml` files. Selected permanent Trash deletion requires typed confirmation, retains receipt tombstones/delivery evidence and reconciles storage including all retained draft references. Rollback, replay, late-event and draft-discard regressions pass.

**Security and honest usage:** no public signup; mailbox authorization on reads/search/export/actions; encrypted private content and Inertia history; no-store responses; suspended/stale sessions and remembered logins invalidated. Managed email cannot be self-changed; self-delete is disabled to preserve accepted mail. Sanitized HTML remains scriptless and sandboxed with remote images blocked. Logical, measured, provider-reported, estimated, unavailable and stale usage stay distinct. Unknown is never shown as zero, and stale outbound usage blocks admission.

**Runtime and recovery:** pinned PHP 8.4 Apache production image, immutable non-root application, bounded resources, safe proxy/host handling, secure encrypted database sessions and effective PostgreSQL `verify-full` TLS checks. Free Render blueprint has no paid worker/cron/disk or automatic deploy. Single-use interactive owner bootstrap has no default password, public claim route or MFA exemption. A guarded isolated PostgreSQL dump/restore drill preserved encrypted MIME/drafts, versions, idempotency IDs, uncertain sends, reservations and the consumed bootstrap latch. The original application key is required for recovery.

**PWA boundary:** original public manifest/icons and exactly allowlisted public-static cache. No private pages/mail/API/attachments/exports cached, no push/background send/forced update reload, and no durable offline-draft claim. Separate attachment upload/preview/download remains disabled; originals can contain retained attachments.

## Remaining release gates

1. **Complete control plane:** resumable domain/DNS/routing/Worker/webhook provisioning with exact diff approval, domain verification/drift views, incident reconciliation and the remaining role/ownership/recovery lifecycle. These are unfinished features, not merely missing credentials. Current supported routine mailbox operations are in-app; initial provider accounts, deployment/secrets and CLI owner bootstrap are explicit owner exceptions.
2. **Actual free accounts and deployment:** confirm Render/Neon/Cloudflare/Resend account eligibility, billing-stop settings, HTTPS/canonical host, Neon certificate verification, effective limits, cold starts and suspension behavior. Render Free cannot provide a production availability guarantee. No deployment occurred.
3. **Real email path:** controlled owner-address inbound MIME, durable D1 storage while PHP is unavailable, import recovery, real Resend acceptance/webhook/delivery/usage, suppression behavior, quota resets and Cloudflare Free CPU measurement. The documented Resend daily-window discrepancy remains unresolved. Keep external sending disabled.
4. **Recovery:** owner-held encryption/MFA recovery material, off-machine encrypted backup retention, actual Neon/D1 restore and provider/idempotency reconciliation. Owner disaster recovery cannot depend on an unavailable app. The local drill does not implement scheduled cloud backups or prove live restoration.
5. **Devices and remaining checklist cases:** physical iOS/Android keyboard, safe areas/rotation/gestures, install/standalone, VoiceOver/TalkBack/NVDA, native text scaling/browser zoom, worker update while editing and other explicitly unrun combinations in the UI report. Emulation and axe are not substitutes.
6. **Pilot feature limits:** metadata search rather than full-text MIME/operator search; basic thread correlation; no separate attachment UI, durable offline drafts or push; public email-password recovery disabled. Export/Trash deletion retains independent delivery/backup copies and does not claim erasure from providers.

Next: finish the bounded provisioning/reconciliation and remaining software acceptance work, then connect owner-controlled credentials through the encrypted interface for live verification. Before any DNS/routing change, show the actual proposed diff and obtain explicit approval. Do not represent pending setup, inaccessible metrics or an untested service as healthy or production-ready.
