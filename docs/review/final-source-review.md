# Final independent frontend source review

Reviewed 2026-11-01 against Assessment A, `DESIGN.md`, and `MOBILE_UX.md`, using the pinned Impeccable critique guidance. This is a **source review**, not a new visual or browser-test pass. No shared browser suite, build, provider request, application mutation, or source edit was performed. Only this report was written. The integration changed during review; findings below distinguish the issue as first observed from corrections subsequently read in source. Assessment B was not consulted.

## Findings and disposition

1. **[P1, corrected in source during review; regression evidence pending] Mark unread immediately marked the conversation read again.** `resources/js/pages/mail.tsx:216` initially reloaded the open thread after `mutate('unread')`. `app/Http/Controllers/MailController.php:51` paginates that thread and line 54 marks its messages read on GET, so the reload reversed the user's action and advanced message versions again. Root added `unread` to the actions returning to the list. Verify both toolbar and More → Mark unread, including an Unread-filtered list; the saved state should remain unread and Undo should remain usable.

2. **[P1, corrected in source during review; regression evidence pending] Conversation-wide action names overstated their scope for long threads.** `mail.tsx:366` derives action IDs only from `thread.messages`; the controller returns 30 messages per conversation page and accepts at most 30 mutation IDs. “Archive conversation” / “Trash conversation” therefore moved only the visible page in a thread with more than 30 messages. Root now names those controls “Archive visible messages” / “Trash visible messages” when the conversation is paginated. This is an honest bounded behavior without adding a new bulk backend operation. Verify the accessible names and resulting folder state on a 31+ message thread.

3. **[P2, corrected in source during review; regression evidence pending] Saving credentials could erase newer unsent input.** `resources/js/components/postroom/admin-controls.tsx:828` clears all values after a successful save. The fields originally remained editable while that request was in flight: a newer pasted key was not part of the submitted payload, then disappeared on success while the old value showed as configured. Root added `disabled={busy}` to connection inputs at approximately line 866. Verify with a delayed save that editing is unavailable until the response, and failed saves retain the original inputs. Unsubmitted values are component memory only; navigating through password confirmation still clears that component state, as the current password-manager guidance warns.

4. **[P2, corrected in source; final integration evidence remains separate] Selection exit and completed More actions lost focus when their trigger disappeared.** `mail.tsx` initially cleared selection from a conditionally rendered button without restoring focus. A successful More action similarly removes its own Sheet trigger. Root now restores Clear-selection focus to the first selected message's surviving open control, with the stable main as fallback, rather than the mobile-hidden select-all input. `resources/js/components/postroom/ui.tsx` restores surviving triggers or the stable main, and its replacement-sheet guard checks the actual focused open sheet rather than any open dialog; an idle persistent composer no longer suppresses restoration. Source rechecked while adding acceptance fixtures. Verify keyboard Clear selection, More → Mark read after a row disappears, and closing Quick settings while a desktop draft remains open. The new acceptance spec also exercises selection exit at 200% text.

5. **[P2, corrected in source during review; regression evidence pending] Suspension errors appeared behind the still-open confirmation dialog.** The Suspend/Reinstate request in `resources/js/pages/admin.tsx` catches errors with `setMessage`, which was initially rendered only in the underlying admin content. Its modal overlay/focus isolation prevented reliable visibility or announcement. Root added a `role="alert"` error inside the confirmation Sheet. Verify a denied operation or disconnected request: the error should be visible within the dialog and permit a deliberate retry without silently closing it.

## Assessment A follow-through

- **Theme and account styling:** `app.css` now maps the shared muted surface and text tokens separately. Settings use `--selected` / `--ink`, and account/auth fields, buttons and navigation have explicit 48 px sizing and 16 px editable text. This addresses the source cause of the measured 2.41:1 active-tab failure. Actual light/dark computed contrast and reflow still require the new build's evidence.
- **Selection:** explicit Clear selection, compact count/scope, and hidden mobile pagination/settings improve the prior toolbar. The normal search header and Compose remain present in source; assess their visual competition in the forthcoming narrow-screen captures rather than claiming the mode is fully isolated.
- **Brand:** login, password confirmation, MFA, settings and admin use the original WebMail mark and “WebMail by Hookstack.” Root's accessible-name fixes were visible during this review.
- **Appearance:** both account controls and quick settings now use the shared appearance updater and `/preferences`; the persistent mail layout initializes from account preferences. The shared OS-theme listener remains active. No second independent account preference endpoint remains.
- **Search:** new searches now cover mailbox mail except Spam/Trash and include recipient metadata; a scope selector allows explicit folders. This resolves the original misleading Inbox-only scope. Mobile scope-control reachability and clear/cancel behavior still need rendered evidence.

## Strengths and evidence limits

One account-keyed persistent layout owns compose across mail, admin, settings and password confirmation. The save/flush path, pending-recipient guard, offline warning, and unload guard remain present; private drafts and provider credentials are not placed into localStorage. Incoming HTML stays in the existing sandboxed endpoint. Original export and administrator changes continue through authorized backend endpoints; visual controls do not replace permission checks. The mobile admin section drawer is now present. Provider status copy distinguishes simulation, access checks, and unverified delivery rather than inventing live success.

No new source-confirmed draft-loss or authorization bypass was found in the reviewed flow. This does not certify every asynchronous/history path. Physical keyboards, VoiceOver/TalkBack, safe areas, 200% text, actual 320 px reflow, updated light/dark contrast, and provider behavior were not exercised here. Root reported seven Chromium failures before this pass and is fixing fixture/accessible-name issues; this review does not reclassify those as passing. Final visual critique should use the updated screenshots and identify their browser/build and viewport explicitly.
