# Gmail reference and WebMail design review

Reviewed November 1, 2026. Product identity: **WebMail by Hookstack**. This document compares the implemented pilot with Google's public Gmail interface and interaction references. It is not a claim of Gmail feature parity or identical production pixels.

## Reference and method

Google's public Gmail design article was opened in a separate browser tab and its interface animations were visually inspected. They show the left navigation, pale Compose action, blue selection, broad search and quick-settings panel. This is public product evidence, not inspection of an authenticated Gmail account. The article is dated July 2022; it is not proof that every current Gmail account has the same interface. Current help pages were also checked for supported layouts, reading panes, search and Android interactions. [Google's Gmail design article](https://blog.google/products-and-platforms/products/gmail/gmail-design-update/), [quick settings](https://workspaceupdates.googleblog.com/2020/05/new-gmail-quick-settings-optimize-inbox.html).

The WebMail review used the pinned Impeccable 3.8.0 guidance, independent [Assessment A](review/assessment-a.md), independent [Assessment B](review/assessment-b.md), source review, Playwright, axe and manual inspection of fictional local screenshots. The detector returned an empty findings array; this is not a usability or security certification. The source pin is in [impeccable-pin.json](impeccable-pin.json). Actual test outcomes and unresolved checklist cases are recorded in [UI_REPORT.md](UI_REPORT.md) and [STATUS.md](../STATUS.md).

| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

[Inbox layouts](https://support.google.com/mail/answer/18522?hl=en&co=GENIE.Platform%3DDesktop)                     | Full-width list → conversation is the default. A restrained left rail, pale-blue Compose, compact aligned rows and unread weight carry the mail hierarchy. No decorative dashboard or unsupported Chat/Meet/AI controls.                                                                                                                              |
| Reading pane                | No split, right or below are available. [Reading pane](https://support.google.com/mail/answer/9499937?hl=en)                                                                             | Optional right pane at sufficient width; it collapses to a full-screen conversation on narrow screens. A below-list pane is outside this pilot.                                                                                                                                                                                                       |
| Search                      | Broad mail search with narrowing controls. [Gmail search](https://support.google.com/mail/answer/6593?hl=en&co=GENIE.Platform%3DDesktop)                                                 | Search now spans the authorized mailbox except Spam/Trash by default; an explicit scope selector includes other folders. Sender, subject and To/Cc metadata are supported. Full MIME/body search and Gmail's operator language are not implemented.                                                                                                   |
| Compose and navigation      | Desktop floating composer and dedicated mobile composition are the familiar model.                                                                                                       | One versioned server draft and its unfinished recipient inputs survive minimize, resize, settings and password confirmation. Save status follows actual saved fields, including layout changes during a response. Mobile has its own full-screen composer/search/reader. Failed saves retain in-view text; offline reload durability is not promised. |
| Mobile selection            | Sender-image selection and configurable swipe actions. | Theme and density           | Quick settings brings theme, density and reading-layout choices together. [Quick settings](https://workspaceupdates.googleblog.com/2020/05/new-gmail-quick-settings-optimize-inbox.html) | Shared persisted theme state across mail and account settings, comfortable/compact rows and optional pane. Corrected conflicting surface/text tokens and dark-mode contrast.                                                                                                                                                                          |
| Authentication and settings | Familiarity should not impersonate Google's authentication.                                                                                                                              | Original envelope mark, WebMail wordmark and “by Hookstack” on login, MFA, reauthentication, settings and administration. Numeric MFA input has a label and one-time-code autocomplete. No Google logo or Google sign-in imitation.                                                                                                                   |
| Administration              | Gmail account and Workspace operations are a different product/control plane.                                                                                                            | Separate phone-friendly section drawer. Owner-controlled encrypted connections; bounded aliases, shared mailboxes, quotas, member access and directory sync. Ordinary members need only a WebMail account. Mock/read-only checks do not imply live delivery.                                                                                          |
| Long mail and recovery      | Dense lists still require usable navigation and deliberate deletion.                                                                                                                     | Paginated lists and conversations, explicit “visible messages” labels for bounded thread actions, safe HTML containment, authorized original MIME export and typed confirmation for permanent Trash deletion.                                                                                                                                         |

## Color system

These are **WebMail's chosen values**, informed by Gmail's visual direction. The official references do not establish Gmail's exact current hex values. Original branding and existing accessible behavior take precedence over pixel imitation.

| Role                 | Light     | Dark      |
| -------------------- | --------- | --------- |
| Canvas               | `#f6f8fc` | `#15191f` |
| Main surface         | `#ffffff` | `#20252d` |
| Primary text         | `#1f1f1f` | `#e8ecf2` |
| Secondary text       | `#545b66` | `#b1bbc8` |
| Navigation selection | `#d3e3fd` | `#284779` |
| Primary action       | `#0b57d0` | `#a8c7fa` |
| Compose              | `#c2e7ff` | `#284c6b` |

WCAG relative-luminance calculations for these token pairs: primary text on the main surface **16.48:1 light / 12.99:1 dark**; secondary text **6.85:1 / 7.93:1**; selected navigation text **12.70:1 / 7.81:1**; action-button text **6.39:1 / 9.14:1**. These calculations cover the named solid-color pairs, not every rendered state or incoming email. Axe checks and manual captures supplement them. Selection, focus, error and unread states also use shape, weight, text or outlines.

## Manual critique and corrections

The initial mail surface already had a recognizable Gmail-like hierarchy. Its strongest problems were at the edges of that workflow: a 2.41:1 settings tab, starter-kit authentication branding, conflicting theme persistence, ambiguous search scope, no mobile selection exit and small account controls. Those are corrected. Settings/auth inputs now use 16 px baseline editable text; principal phone controls use 48 px targets. Long forms retain a visible close control, with an opaque header over scrolled content.

The reviewed desktop screenshot has a broad coherent list, quiet borders, a distinct Compose action and aligned sender/subject/date columns. The 320–390 px screenshots use a separate mobile header and full-screen reader; they do not compress three desktop columns. Enlarged account text wraps and remains readable. A later manual review caught fixed line heights clipping enlarged mail rows and a wide table squeezed into 18 px columns. Both were reproduced by new assertions, corrected and visually checked: row height now follows text size, and readable table columns scroll inside the sandbox. Connections clearly labels simulation and bootstrap limits. The remaining mobile evidence gaps are keyboard, safe-area, install and assistive-technology behavior on physical devices; neither screenshots nor browser engines resolve them.

The initial independent review scored 26/40 within its limited scope. No replacement score is invented after remediation. See the final screenshot paths and executed workflow results in the UI report. Live provider readiness, complete domain provisioning and reliable hosting remain separate release work.
