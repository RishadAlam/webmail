# WebMail by Hookstack UI acceptance report

**Date:** November 1, 2026. **Build:** November 1 WebMail review, branding, administration and safety changes; see [STATUS](../STATUS.md) for the final build/test record. This is an execution report for [UI_ACCEPTANCE.md](../UI_ACCEPTANCE.md), not a production/mobile certification.

## Environment and evidence

Playwright 1.64.1 on Linux: Chromium 156.0.8078.4, Firefox 157.0, WebKit 27.2. All browser flows run against the actual Laravel application, isolated SQLite database and deterministic outgoing provider. PostgreSQL authorization, quota and concurrency tests run separately. No actual email is sent. WebKit uses the official Playwright binary with missing Ubuntu libraries unpacked under `/tmp`; it is not iPhone Safari.

**Login/startup follow-up:** the Docker HTTP preview had fallen back to `.env` SQLite despite PostgreSQL working in CLI checks. Local startup and Playwright now explicitly use `--no-reload` to retain inherited environment settings. The host and container have different PHP environment handling; these browser runs must not be used as evidence for Docker's database choice. A separate real HTTP PostgreSQL startup/MFA regression and a fresh session on the restarted preview both passed. All three browser suites and their captures were repeated after the configuration fix. No physical-device evidence was added.

Additional acceptance fixtures: the testing-only `BrowserAcceptanceSeeder` adds a separate authorized Acceptance Lab mailbox with 78 fictional records: 45 independent conversations, a 31-message conversation, a wide HTML newsletter and 20-recipient details. It refuses any database except the exact disposable `storage/e2e.sqlite`. The original inbox counts are unchanged.

Fixtures: `DemoSeeder`'s Mira Chen/member and Alex Morgan/owner; 17 fictional messages (`fixture-1` through `fixture-17`), long international sender, long and empty subjects, and drafts created by the browser tests. Owner MFA is exercised with the public fictional TOTP seed. Two owner logins wait for distinct codes; replay protection remains enabled. The browser server's daily cap is deliberately **2 recipients**, so a two-recipient draft is held at the 95% admission boundary. This is a test configuration, not a provider measurement.

Viewports: 320, 360, 390, 430, 768, 1024 and 1440 CSS px, height 900 for inbox captures; 390×844 for mobile administration/routes; 430×740 for composer; 320×568 for reduced-motion composer; 1440×960 for desktop interactions. Light inbox and dark compact reading-pane/composer states are checked. Resizing exercises layout transitions, not physical rotation/keyboard behavior.

Evidence paths:

- `ui-evidence/inbox-{320,360,390,430,768,1024,1440}.png`: reflow captures; final matrix capture is Chromium (each engine runs the same matrix).
- `ui-evidence/desktop/{chromium,firefox,webkit}-dark-pane.png`: settled optional pane and collapsed navigation.

Tests in `tests/e2e/mail.spec.ts`, `review.spec.ts` and `acceptance.spec.ts` are referred to below by their workflow names. Final complete runs passed **31 workflows per engine, 93 total**: Chromium 1.4m, Firefox 1.8m and WebKit 1.9m. They include the readability and composer fixes; historical passes are not substituted for these runs. **Passed** means the stated local check passed. **Not run** means a required subcase still lacks direct evidence; any completed subcases are listed explicitly. **Blocked** identifies missing implementation or unavailable physical/live resources. No blanket pass is inferred from screenshots or axe.

### Manual critique and remediation

The desktop hierarchy reads as mail: broad search, distinct Compose, restrained navigation, aligned rows and clear unread weight. The default surface is a list; the optional reader earns its extra width. The 320–430 layouts use a separate header, touch rows and full-screen composer instead of squeezed desktop columns. Dark mode keeps the reader and controls legible, and usage becomes a readable vertical list on a phone.

Manual/browser review found and fixed: clipped account control at 320, inaccessible collapsed-rail names, hidden mobile paging/refresh, missing dirty Cc text after minimize, close/navigation races, a displaced settings fieldset, and mobile history that previously exited the app. Screenshots were changed to wait for settled reader/saved-draft states rather than capturing transient disabled rows. Small measured percentages now say `<1%` instead of rounding positive consumption to zero.

The remaining evidence gaps above are release work, not implied passes. Priority: physical iOS/Android keyboard/install/safe areas and assistive technology; native zoom and gesture edge cases; service-worker update while editing; complete domain/DNS/provisioning and live recovery workflows. No “fully tested mobile”, “offline mail”, Gmail parity or go-live claim is made.

After the login/startup fix, the refreshed 390 px inbox and mobile Usage captures were inspected again: single-pane mail hierarchy, readable usage values, explicitly unavailable provider measurements and pending provisioning remain visible. This was a screenshot review, not a physical-device test.

## November 1 review follow-through

The [Gmail comparison](GMAIL_COMPARISON.md) records official public references, chosen colors, contrast calculations and manual visual critique. [Assessment A](review/assessment-a.md), [Assessment B](review/assessment-b.md) and the [final source review](review/final-source-review.md) keep independent findings separate from executed browser evidence. The initial 26/40 limited review score has not been replaced with an invented post-fix score.

New regressions cover branded/labeled MFA, managed account identity, shared theme persistence, draft/search preservation across password confirmation, mobile selection/focus, Mark unread returning to the list, bounded long-conversation labels, actual owner mailbox/alias/directory/connection changes and explicit permanent deletion. The independently discovered Trash quota error failed in four saved/immutable-draft cases before correction and passes afterward. Provider assertions are simulated or contract tests; no real mail was sent.

Manual review of the enlarged-mail screenshot found clipped/overlapping text despite the earlier shell-overflow assertion. Relative row line heights and scalable date columns correct it; the new regression failed before and passes after. A wide-table screenshot likewise showed 18 px columns; protected HTML now keeps readable minimum cell widths and allows horizontal scrolling to the last column inside the sandbox. Both corrections retain the outer-shell containment and remote-content restrictions.

An intermediate Firefox run exposed a composer remount race, reproduced with controlled response timing: the server had saved the message but the UI could remain Not saved yet. A second regression reproduced unfinished Cc loss during the desktop/mobile transition. Pending recipients now belong to the persistent compose provider, clean saves normalize the indicator, and queued saves recheck the active promise. Both new regressions pass in all three final complete suites; they do not claim offline persistence.
